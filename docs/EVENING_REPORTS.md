# 時間外分析・翌営業日レポート（Windows）

## まず保存済みデータで確認

プロジェクトフォルダで、仮想環境を有効にして実行します。

```bat
.venv\Scripts\activate
python kabu_system.py evening-report --config config/paper.json
python kabu_system.py run-status --config config/paper.json
python kabu_system.py analysis-preview --config config/paper.json
```

この3コマンドは外部通信・課金・注文を行いません。`evening-report` は新しい出力フォルダにHTML・JSON・グラフを書きます。収集DB・AIキャッシュ・口座・予算台帳は読み取り専用です。`run-status` と `analysis-preview` はDBを新規作成しません。

出力先は `data/operations/reports/evening_日時/`。表示された `report.html` をエクスプローラーからブラウザで開いてください。HTMLと同じ場所のPNGが必要です。スマホからは既存のリモートデスクトップでこのHTMLを開きます。Webサーバー・公開URL・遠隔注文機能はありません。

HTMLを開き直しても予測を再計算しません。コマンドの再実行は別フォルダに新しい分析を保存します。任意の `--output` は未使用のフォルダを指定してください。既存レポートの上書きは拒否します。

## MAとLightGBM

既定はMAの5/20クロスです。今回確認した保存済みチャートモデルを使用する場合:

```bat
python kabu_system.py evening-report --config config/paper.json --model data/system_chart_model_v1
```

これは例の保存先です。実際の `manifest.json` と `model.txt` が入ったフォルダを指定してください。恒常的に使う場合は設定の `chart` を次の形式にします。

```json
"chart": {"strategy":"lightgbm","model":"data/system_chart_model_v1","threshold":0}
```

モデルの出力期間をそのまま表示します。現行の5営業日後リターンを翌日リターンや上昇確率として表示しません。MAの方向、LightGBMリターン、ニュースの事業への好悪材料、統合後のBUY/SELL/HOLD/NO_TRADE/ERRORを区別します。モデルが未来に作成された場合、読み込み失敗、取得元不一致等はERRORで保留します。モデルの学習方法・特徴量は変更していません。

レポート候補は注文予約ではありません。翌日の仮想売買は、その時点の新鮮な価格・企業行動・リスク条件を用いる既存の処理です。

## 日足の確定・休場日

- 既存XTKS営業日カレンダーで分析対象日と次の営業日を判定します。土日・休場日は直近営業日の足を使用。
- 取引日の16:00 JSTまでは当日足を未確定扱いにし、翌営業日の候補は保留します。16時は配信元の確定保証ではなく、このシステムの保守的な利用境界です。
- 対象日の足がない、履歴に営業日の欠落がある、対象足を終了前に取得した等はERROR。古い足を当日の足として代用しません。
- 取得時刻・利用可能時刻が分析時刻より未来の足とニュースは判断に使いません。後日取得したデータを取得前から保有していたことにもできません。
- runtimeの日足取得は16時以降なら当日分も保存対象にします。従来の単独 `yahoo_history.py` の当日除外は維持しています。Yahooの配信が遅れれば足は揃わず保留です。

JSONは分析日時、モデルメタデータ、入力足・ニュース、口座・キューのスナップショット、設定、入力ハッシュ、予測と最終判断を保持します。機密情報を設定JSONに入れないでください。元DBは履歴を全世代保持するものではないため、保存したレポートが分析時点の記録になります。

## 収集と自動レポート

```bat
python kabu_system.py run --config config/paper.json
```

ニュース・株価の取得条件、APIキーの環境変数、停止方法は [継続運転ガイド](CONTINUOUS_OPERATIONS.md) を参照。`network_enabled: true` でも `dry_run: true` なら有料ニュース解析は実行しません。今回の開発では利用者の既存の通信設定を変更していません。

自動レポートは既定で無効です。`config/paper.json` のトップレベルに次を追加し、Botを再起動してください。

```json
"evening_report": true,
"analysis_max_age_hours": 24
```

既存JSONへの追加なので、前後のカンマに注意してください。日足ジョブは通常の間隔に加え、16時以降の最初の巡回で更新を試みます。失敗時は既存の待機間隔を守ります。レポートの準備確認は5分間隔で、全監視銘柄の必要な終値が揃った場合に出力。同じ入力日足・モデルは再起動後も重複出力しません。後日の取得で足が更新されれば別レポートになります。ニュースだけの更新では自動再生成しないので、必要なら手動コマンドを実行します。

企業行動未確認による仮想売買停止は維持しています。停止中でも、独立した収集と分析レポートは実行できます。PCの電源・スリープ・kabuステーションのログイン状態は利用者が整える必要があります。Windowsログオン時の自動起動設定は今回追加していません。

## 市場・業種RSSが0件だった原因と修正

旧実装は `"日銀 金融政策 政策金利" when:7d` のように検索語全体を一つの完全一致フレーズにしていました。複数キーワードを広く探す意図と異なり、結果を絞り込みすぎる構造でした。

今回、企業名の完全一致は維持し、市場・業種は括弧付き検索に分離。旧 `query` の空白区切り語はOR検索に変換します。個別に検索したい場合は既存のtopic要素を次のように変更できます。

```json
{"id":"usa","scope":"market","queries":["米国 CPI","米国 雇用統計","FRB 政策金利"]}
```

これらは別検索で、`@market:usa:0` 等のキーと検索式を保存します。URLが同じ記事は既存の保存処理で統合し、検索への一致と企業への関連性を分けて保持します。AIが関連性を確認しない限り、全銘柄に好悪材料を付与しません。

正常な空RSSは `ok / 受信0件`。不正XML・不正項目・通信失敗は `failed`。一部不正の応答も正常な0件とは扱いません。`run-status` とHTMLのRSS詳細で各検索の最後の結果を確認できます。旧検索キーの履歴は削除せず残します。

検索URL・識別子・保存・正常0件/失敗の区別は模擬RSSで検証済みです。修正後の実Google RSSで何件取得できるかは未検証で、取得件数や速報性は保証しません。

## 解析待ちと送信前確認

```bat
python kabu_system.py analysis-preview --config config/paper.json
```

- 状態別件数、除外予定/除外済み理由、優先候補、次回バッチ上限、予算上送れる見込み件数、実際の送信予定件数、日次/月次の使用・残予算を表示します。
- 初期DRY_RUNで送信予定は0件。単価未設定でも送信しません。予算は既存のUTC日/月区切りで、円換算レートは設定上の仮定です。
- 既定は公表・初回取得の両方が過去24時間以内。古い記事を今取得しても新着材料として送信しません。日時不明・未来・古い記事を除外し、次のruntime解析巡回時に `queue_exclusions` に理由を保存。
- 古さによる除外と、日時不明・不正による除外は区別します。後者は好悪未確認として新規買いを抑止し、関連ニュースなしとして扱いません。
- 重要な業績修正等、本文あり、企業別候補の順に加点し、同順位は公表の新しい順。これは送信の優先順位で、株価の上昇スコアではありません。
- 重複キュー・成功済み解析を再送しません。1巡回は既定3件。日次・月次の送信前予算予約は維持。過去の失敗/未完了の送信も自動再試行しません。
- `analysis_max_age_hours` は0超～168以下で変更可能。除外済み記事は値を変えても無条件に復活させません。除外の手動復活UIは未実装です。
- プレビューは待ちキューの読み取りです。まだruntimeが巡回していない新着記事をキューへ追加する機能はありません。プレビュー後に状態が変われば送信予定も変わります。

## 状態確認・停止・再開

```bat
python kabu_system.py run-status --config config/paper.json
python kabu_system.py paper-report --ledger data/operations/paper.sqlite3
```

`run-status` はJST付きの処理履歴、現在値の最終受信、ニュース/日足、解析待ち、DRY_RUN、資金・保有・損益、停止理由を表示。市場が閉まっているため価格ジョブが動かない場合は「市場時間外」と区別します。口座の資産・損益は最終保存評価であり、古い価格を使って現在の評価に書き換えません。

ハートビートは直近の巡回があったことの目安です。長い通信や処理中は更新が遅れ、停止と区別できない場合があります。旧バージョンにはハートビートがないため、起動未確認と表示されることがあります。

Ctrl+CでBotを停止し、同じ `run` コマンドで再開します。新規買いのみ止める既存の停止ファイルも利用可能です。企業行動確認を省略する設定は追加していません。

## 検証範囲

既存114テストを維持し、時間外・休日・未来情報・欠損・出力固定・エスケープ・予算付きキュー・RSS・自動レポート等15件を追加。既存テストの2つのニュースfixtureには新しい日時要件を追加し、オフライン試験は利用者の通信設定に依存しないよう明示指定しました。

保存済み10銘柄と既存LightGBMモデルでHTML/JSON/グラフ、5営業日予測の生成も確認。有料API・実注文は実行していません。実市場の耐久運転、実RSSでの修正後件数、ニュースAIの新しい精度評価、企業行動の自動取得、PTS・公開Web・モデル改良は対象外です。

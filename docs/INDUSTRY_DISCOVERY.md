# 経済・産業ニュースから関連銘柄を発見する

既存のニュース収集・MA・LightGBM・仮想口座を残し、分析候補を別DBに保存します。新発見銘柄を監視リストや仮想口座へ自動追加する機能はありません。本文/見出しの好悪材料分類は、株価上昇確率や期待リターンとは別です。

## Windowsでの初回確認（課金なし）

プロジェクトのフォルダーで実行します。既存の仮想環境・requirements-operations.txtの依存関係を使用します。

```bat
.\.venv\Scripts\python.exe news_discovery.py companies-import --file config/companies_sample.json
.\.venv\Scripts\python.exe news_discovery.py companies-list
.\.venv\Scripts\python.exe news_discovery.py preview
.\.venv\Scripts\python.exe news_discovery.py run --dry-run
.\.venv\Scripts\python.exe news_discovery.py list
.\.venv\Scripts\python.exe kabu_system.py evening-report --config config/paper.json
```

`preview`は読み取り専用。`run --dry-run`は設定にかかわらず有料APIを呼ばず、ローカル語彙で探索した候補を「解析待ち」として保存します。表示されたレポートのHTMLをブラウザで開いてください。JSONにも企業情報・出典・期間別影響・チャート結果・見送り理由が保存されます。ニュースや株価の取得通信はこの6コマンドに含まれません。

対象ニュースは **config/paper.jsonのpaths.news / paths.documents** です。古い`data/news.sqlite3`とは保存先が異なります。直近7日以内に初めて保存されたニュースを読み、本文登録があるURLでは本文を優先します。空なら収集を先に行います。既存の継続運転で`network_enabled=true, dry_run=true`に設定すると無料RSS/価格等の通信を行い、AI送信・仮想注文を止めて収集できます。

```bat
.\.venv\Scripts\python.exe kabu_system.py run --config config/paper.json --once
```

この収集コマンドはネットワーク通信を伴います。設定のdry_runがfalseの場合は既存AI処理や仮想口座処理も動くため、収集だけなら必ずtrueを確認してください。今回の開発作業では実行していません。

## 処理と保存

1. 保存済みニュースを内容・公表時刻等で重複排除。モデル・形式・入力のハッシュで結果をキャッシュします。
2. 第1段階AIに1記事と産業タグ語彙を渡し、産業、影響の仕組み、遅延、事実/計画、引用、不明点を厳密なJSON形式で抽出させます。
3. 企業DBをローカル検索。企業名の直接記載と、事業タグによる間接候補を区別します。DB全体をLLMへ送りません。
4. 上位候補だけを1社ずつ第2段階AIに渡し、短期/中期/長期の好悪材料、事業関係、条件、ニュースと企業資料の引用を保存します。
5. 解析完了・企業情報登録・記事取得の各時刻以降だけ、研究用チャート統合に利用します。チャートの予測値は書き換えず、好悪材料・不明情報で候補を絞ります。予測期間と選択期間の不一致は保留します。

既定保存先は`data/operations/companies.sqlite3`と`data/operations/discovery.sqlite3`。企業改訂・入力・モデル・使用量・エラー・候補・観測結果を追跡できます。企業DBはsymbol単位の改訂履歴で、同一内容の再登録は冪等です。更新時はupdated_atも更新してください。確認日が過去でも、今回登録した企業情報を過去の判断に遡って使いません。

企業情報の項目はコード、名称、別名、業種、事業、更新日、事業関係の配列。各関係には産業タグ、役割、確認状態、直接事業の有無、出典URL、引用、確認日、売上/利益比率と根拠を持ちます。未知の比率はnullです。URL・引用の形式検証は行いますが、インポート時に資料を再取得して真偽を確認する機能はありません。人が出典を確認して登録してください。

## 有料解析を後日使う場合の準備

今回は実APIを呼びません。後日利用する場合は、設定のllmに対応する料金をconfig/budget.jsonへ登録し、日次・月次上限、OPENAI_API_KEY環境変数、network_enabled=trueを用意します。dry_run=falseにして`news_discovery.py run`を実行すると有料送信になります。キーはソースやJSONへ書きません。最初は`discovery.max_calls=1`で1記事の産業解析だけ確認し、次回キャッシュを使って企業別解析へ進めます。

新経路は既存DailyBudgetの予約・精算を必須とし、失敗は自動再送しません。中断状態も勝手に再送せず保留します。モデル/入力/形式を変えると別の課金対象です。構造と引用一致を検証しますが、意味の誤読や過大評価は残るので根拠の確認が必要です。スコアの重みや未学習の確率は生成しません。

config/paper.jsonには任意で次のdiscovery項目を追加できます（トップレベルの他の設定は維持）。追加しなくても上のCLIは使えます。

```json
"discovery": {
  "enabled": false,
  "max_candidates": 5,
  "max_calls": 3,
  "horizon": "short",
  "periods": {"short": [1, 5], "medium": [20, 60], "long": [120, null]},
  "allow_indirect": false,
  "min_turnover": 100000000,
  "max_reaction": 0.03,
  "timeframes": {},
  "benchmarks": {}
}
```

enabled=trueで既存ランナーの解析ジョブ成功後に発見処理を実行します。max_callsは**発見処理だけの上限**で、既存解析のanalysis_limitとは別です。双方で共通予算を使います。企業別解析は記事ごとにmax_candidates社までで、それ以外も分析候補として保存されます。

timeframesにはshort/medium/longごとにchart_model（保存済みLightGBMフォルダー）とrisk（既存RiskLimitsの上書き）を設定可能です。研究用コピーだけに反映し、稼働中の仮想口座設定は変えません。ニュース専用学習モデルnews_modelは未実装のためnull以外を拒否します。期間ラベルはモデル精度の保証ではありません。現状は公表後7日以内の材料だけを判断に用いるため、中長期の材料継続・失効管理は今後の課題です。

## 観測結果とバックテスト

```bat
.\.venv\Scripts\python.exe news_discovery.py outcomes
.\.venv\Scripts\python.exe news_discovery.py backtest --output data/discovery_backtest_01.json
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

outcomesは保存済み株価だけで1/5/20営業日後の変化を追記します。ニュース受信直前60秒以内の実tickがなければ取得時点価格はnullです。最初のニュース後終値からの変化は別の代理指標として記録し、欠損・未到来はゼロで埋めません。分割を換算し、配当は含めません。benchmarksに`{"TOPIX":{"db":"絶対パスの共通日足DB","symbol":"データ内のコード"}}`等を与えた場合だけ相対変化を計算します。指数データ自体は取得しません。結果ラベルは予測入力に戻しません。

ニュース単独バックテストは既存監視銘柄のみ、確認済み材料、分析後2本以上の観測終値、流動性、コストを超え追随上限以下の反応を条件にし、既存の次足始値約定・独立リスク制御を使用します。取得/解析時刻を尊重するrecordedモードなので、後日取得した過去データでは取引ゼロになり得ます。出力名は未使用のものを指定してください。仮想口座台帳は変更しません。

## 現在の範囲と検証

研究用レポートではチャート＋材料、悪材料による買い抑制、重大悪材料の保有見直し、ニュース単独候補、不明時保留を区別します。実行可否は常にfalseです。発見結果の継続仮想売買への自動投入、ニュース専用予測モデルの学習、全企業の事業データ自動収集、相場全体を網羅した実績評価は未実装です。

架空のA〜E（資源発見、役割別影響、企業明記、金融政策、不明ニュース）を使い、重複/キャッシュ/予算/時刻漏洩/引用捏造/注文対象不変/翌営業日レポート/期間別設定をテストします。APIはモックのみです。

2026-09-23の確認では、全151テスト成功（既存129＋追加22）。実際の保存済みニュースのdry-runでは269件の記事×銘柄候補を保存し、既存監視外は8035、企業別解析は全件pending、発注可能件数0でした。これは269銘柄という意味ではありません。初期12社を新DBへ登録し、HTML/JSONを生成しました。有料API呼出し・実注文・既存データ削除は0件です。matplotlib依存の非推奨警告はありますが、テスト失敗はありません。

中断時の自動レビュー失敗は利用制限で審査が完了しなかったもので、安全性の指摘による却下ではありませんでした。未適用だったnews_discovery.pyとdiscovery_integration.pyの期間別設定を再確認し、設定検証・コピーによる研究限定適用・期間不一致時の保留とテストを加えて通常の編集手順で適用しました。
